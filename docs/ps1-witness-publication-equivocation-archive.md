# Stage 264F — private conflict-evidence retention with independently pinned readback

Stage 264E identifies two complete, correctly co-signed and contradictory
checkpoint successor claims **without asserting either was committed**.
Stage 264F saves enough bytes to reproduce that evidence and detect later
alteration or loss **relative to an independently retained archive pin**.

The new local reference tool is:
tools/audit_record_witness_publication_equivocation_archive.py

The tool's create action takes all 12 Stage 264E signed envelopes (six per
branch), their exact-byte SHA-256 pins, the two enrolled operator public key
files and external PEM SHA-256 pins, the separately authenticated original
parent generation/pair/event chain head and previous transition bundle hash,
and an independently authenticated expected Stage 264E canonical evidence
SHA-256.

It re-verifies all 12 Ed25519 signed envelopes against the expected fork
evidence **before** touching the archive path. It encodes the complete
envelopes as canonical base64 inside a deterministic JSON document, along
with pins and enrollment metadata. The serialized bundle has a strict 64 KiB
limit, and the reference implementation:

- Requires a private (mode 0700), owner-controlled parent directory.
- Uses exclusive O_CREAT/O_EXCL with O_NOFOLLOW; never replaces an existing
  archive, even when an attempted previous write may have been interrupted.
- Flushes and fsyncs the created file and its parent directory.
- Reopens via a new read-only file descriptor; checks no symlinks, no
  hardlinks, ownership, private permissions, inode identity and file size.
- Checks exact SHA-256 of the serialized archive and **re-verifies both
  branches' signatures** on the readback before it returns a success report.

The create result contains an archive_sha256, which the operator **must
retain separately** from the local archive and from the source/custodian
hosts. The later inspect action **requires** that independent archive hash,
the independent expected evidence hash and enrolled PEM key hashes. It
rejects missing files, truncated/modified files, duplicate fields, invalid
base64, noncanonical JSON, unsafe paths, wrong pins and forged signatures.
A deleted archive cannot be silently regenerated by inspect.

The CLI supports create and inspect, with common mandatory arguments:

    python3 -m tools.audit_record_witness_publication_equivocation_archive \
      inspect /private-operator/forks/case-001.json \
      --operator-a-public /private-operator/keys/a.pem \
      --operator-b-public /private-operator/keys/b.pem \
      --operator-a-pin INDEPENDENT_OPERATOR_A_PEM_SHA256 \
      --operator-b-pin INDEPENDENT_OPERATOR_B_PEM_SHA256 \
      --evidence-sha256 INDEPENDENT_STAGE_264E_EVIDENCE_SHA256 \
      --expected-archive-sha256 INDEPENDENTLY_RETAINED_ARCHIVE_SHA256

The create action additionally takes the same Stage 264E enrollment metadata
and two groups of six --left-* / --right-* envelope paths and exact-byte
SHA-256 values:

- --scope, --operator-a-id, --operator-b-id
- --parent-old-a-sha256, --parent-old-b-sha256
- --previous-transition-bundle-sha256
- --expected-parent-generation, --expected-parent-pair-pin,
  --expected-parent-event-head
- For each of left/right: --old-a, --old-a-sha256, --old-b,
  --old-b-sha256, --new-a, --new-a-sha256, --new-b, --new-b-sha256,
  --endorsement-a, --endorsement-a-sha256, --endorsement-b,
  --endorsement-b-sha256, all prefixed with that side.

Example for one pair of required file arguments:

    --left-old-a /private-operator/input/old-a.json \
    --left-old-a-sha256 INDEPENDENT_LEFT_OLD_A_SHA256

Exit code 0: created and independently reread a local archive, or verified
an existing archive against the externally supplied hashes. Exit code 1:
fail-closed evidence conflict, invalid input, unsafe path or missing archive.
The CLI never dumps raw signed envelopes or key material. If fsync or
readback fails **after** exclusive creation, the file may already exist.
Do not silently retry or overwrite it; inspect it with trusted pins.

## Limits

No external retention is actually deployed. A private local file and local
filesystem fsync do not prove physical durability under power loss,
hardware write caching, remote or administrative independence, global
latestness, WORM/immutable storage, external retention of the returned
SHA-256, or tamper/deletion *prevention*. If the attacker deletes the file,
the independently retained archive SHA enables **detection**, not recovery.

The archive also does not prove either conflicting claim was accepted or
committed by the keeper. It does not execute custodial mutations, retire
witness fences, retry an ambiguous CAS, contact real authorities or build
Nintendo Switch software. Tests use only synthetic Ed25519 evidence and
private temporary filesystem directories.

Every successful report explicitly leaves the following false:
external_archive_custody_proved,
externally_retained_archive_pin_proved,
tamper_or_deletion_prevention_proved,
physical_durability_proved,
either_branch_keeper_commit_proved,
global_latest_head_proved,
automatic_cas_retry_authorized,
witness_fence_retirement_authorized,
witness_fence_retired,
native_switch_game_build_verified.
