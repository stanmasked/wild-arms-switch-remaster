# Stage396 — настоящая холодная перезагрузка ARM в NeXium

В Stage395 подтверждён [GitHub Actions #39557772089](https://github.com/stanmasked/wild-arms-switch-remaster/actions/runs/39557772089):
обычный бой и отдельная ARM-тренировка прошли через **два реальных
процесса NeXium**. Все **12 из 12** Xvfb/SDMC проверок успешны:
магазин 3/3, один выстрел 2/3, удержание без второго выстрела,
обычная защита до следующего раунда, Minus-перезарядка 3/3,
возвращение на карту. В изолированном SDMC ARM не создаёт файлов
сохранения. Архив оригинальных восьми PNG (1600×900), отчётов,
SHA-256, PID и журналов: GitHub artifact `12326049748`.

## Новое испытание: третий реальный процесс

Дополняет тот же маршрут **третьим отдельным запуском NeXium**:
после полного завершения гостя ARM с подтверждённым exit code
новый NeXium стартует **из того же самого каталога SDMC**,
но в новом процессе.

1. Во второй сессии после первой перезарядки ещё два героя
   защищаются и ARM выполняет **второй реальный выстрел**. Перед
   закрытием обязательно снимается дополнительный кадр,
   подтверждающий **2/3 патрона и поверженного врага**.
2. Новый ручной запуск: на карте тот же центральный фрагмент.
3. Повторный ZL+R открывает ARM **со свежими 3/3 патронами**.
   Перед выключением прежняя сессия уже использовала Fire и Reload.
4. Проверяются неизменность всей панели магазина и центрального
   боевого кадра относительно самого первого входа ARM: это
   одновременно доказывает отсутствие сохранённой потери HP
   и отсутствие сохранённого расхода патронов.
5. B возвращает на прежнее поле без записи каких-либо файлов в
   уже существующий каталог игры на том же SDMC.
6. Процессы первого, второго и третьего запуска имеют разные
   реальные PID NeXium; третий имеет собственный `wait` и
   завершение TERM либо явно зарегистрированным KILL.

Новый строгий скрипт `tools/audit_nexium_arm_cold_boot.py`
читает четыре новых реальных PNG в отдельном подкаталоге
`arm-guest/coldboot` и проверяет **8 дополнительных условий**.
Старый анализатор с 12 условиями и восемью PNG не изменён.
Снимки не создаются host-прототипом и не подменяются синтетикой.

Девять синтетических unit-тестов отдельно от настоящего эмулятора
проверяют анализатор: израсходованные патроны после перезапуска,
грязный SDMC, повторный PID, неподтверждённый SIGKILL, плохие
PNG и ошибочное возвращение на карту. Вместе с 13 предыдущими
получается **22 теста**, запускаемых на Intel Mac.

Важно: Stage396 не добавляет сохранение ARM-патронов. Оно
наоборот доказывает их **намеренную непостоянность** и проверяет,
что уже подтверждённые WABJ v1 и полевые файлы не изменялись.
Сборка оригинальной игры PlayStation и физическая Switch не
проверяются. Положительный результат этой новой задачи допускается
только после завершения нового GitHub Actions NeXium workflow.
