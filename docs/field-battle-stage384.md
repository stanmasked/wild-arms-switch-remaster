# Stage 384 — реальный процесс CLI восстановления

В этом исследовательском этапе тестируется команда
`tools/stage_verified_battle_backup.py` через настоящий дочерний процесс
Python, а не только прямой вызов функции в тестах.

## Точный объём

Пять тестов передают реальным CLI-процессам синтетические WABJ-пары
(формат 52 байта) из временных каталогов:

1. Предпросмотр без `--execute` возвращает JSON и не создаёт каталог.
2. `--execute` публикует **только** `battle-progress.a` и манифест,
   подтверждает SHA-256, сохраняет исходные повреждённые A/B и резервные копии.
3. Повторное выполнение с тем же путём завершается с кодом 2 и ничего
   не перезаписывает.
4. Неверная внешняя SHA-256 приводит к коду 2 без выхода.
5. Действительный, неповреждённый исходный слот блокирует восстановление
   и не приводит к изменению файлов.

Проверка устанавливается в самостоятельную GitHub Actions матрицу:
Ubuntu Linux и macOS 15 Intel, Python 3.11 и 3.13. Она дополняет
38 тестов файловой системы и 19 синтетических тестов снимков NeXium:
**62 отдельных тестовых сценария** в каждой конфигурации, если сборка
их успешно выполнит.

**Ограничение:** хотя тестовые программы действительно запускаются
на Linux / Intel Mac, их содержимое полностью синтетическое; никакие
настоящие пользовательские сохранения, файлы оригинальной PlayStation
или физическая Nintendo Switch не используются.

Подтверждение гостевого восстановления 4 побед, 32 EXP и 48 Gella
остаётся за [успешным NeXium CI №39499540088](https://github.com/stanmasked/wild-arms-switch-remaster/actions/runs/39499540088)
по родительскому PR №61. Этот этап не заменяет и не меняет тот результат.
