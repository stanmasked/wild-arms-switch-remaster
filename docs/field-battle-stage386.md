# Stage 386 — управление ARM отдельными фронтами нажатий

Разработан отдельный тестируемый адаптер `field_battle_arm_controller.hpp`
для экспериментального огнестрельного оружия первого персонажа.

- Выстрел и перезарядка требуют **нового нажатия**: удержание не создаёт
  повторную атаку даже после смены раунда.
- Одновременные Fire/Reload не выполняют ни одно из действий. Отпускание
  лишь одной из кнопок не превращается в отложенную атаку.
- Отказ (`Empty`, `AlreadyFull`, недопустимый действующий персонаж)
  не изменяет боевое состояние и боезапас; занятые фронты нажатий при
  этом поглощаются до отпускания кнопки.
- Недопустимое состояние боя/курсора не потребляет ни один фронт,
  поэтому после его исправления следующее корректное событие будет
  обработано обычным образом.
- Если выбранный враг уже побеждён, при успешном выстреле выбор
  переносится на другого живого врага.
- После успешного действия курсор пропускает героев, завершивших ход,
  в соответствии с существующими правилами боя.
- Сохранены прежние кнопочные защёлки A/Y. Сам адаптер не подключён
  к Switch и не изменяет нейтральный ввод полевого исследования.

Новый CTest исполняет шесть сценариев: удержание выстрела, одновременные
кнопки, полноценный ход перезарядки и ответ противников, выбор живого
врага, пустой магазин, повреждение игрового состояния.

Этот этап **не внедряет команду в текущий NRO и не меняет WABJ v1**:
заряды остаются исключительно оперативным состоянием отдельного
экспериментального модуля. Исходные Wild Arms ARM параметры и анимации
ещё не реконструированы. Результат необходимо подтвердить нативным
C++ CI и только затем проектировать подключение к UI.
