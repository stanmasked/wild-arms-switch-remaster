# Stage 389 — изолированная экспериментальная сборка ARM для NeXium

## Реализовано
Первое необязательное подключение полного тренировочного экрана ARM
к настоящему циклу контроллера `switch/source/main.cpp`.

Новый режим существует **только** в сборке с флагом
`make -C switch WA_ARM_EXPERIMENTAL=1`. Стандартный NRO, включая
пройденные маршруты NeXium, собирается без нового режима.

Вручную, после выключения autoplay:

- **R** — существующий обычный бой; не меняется.
- **ZL + новое нажатие R** — экспериментальная тренировка ARM, только
  если предыдущая боевая сцена не активна.
- **X** — Fire (выстрел) в этой тренировке.
- **Minus** — Reload (перезарядка) в этой тренировке.
- **A / Y / D-pad** — обычный удар, защита, выбор бойца и цели.
- **B** — закрытие тренировки. Без записи наград, патронов или результатов
  в постоянное хранилище; поле рисуется обычным образом, без наложения
  старого меню/уведомления поверх завершающего кадра тренировки.
- **Plus** — стандартный выход из NRO.

Пока тренировочный экран активен, навигация по миру, сохранение,
загрузка и события получают нейтральное управление. Для запуска ARM
не используются оригинальные ресурсы PlayStation.

## Защита существующих данных

- В обычной сборке `WA_ARM_EXPERIMENTAL` не определён.
- ARM не изменяет 52-байтный формат WABJ v1 и не записывает файлы SDMC.
- Обычный R-бой, встречные ZR-бои, Y/Minus-сохранение поля и учёт
  4 побед/32 EXP/48 Gella остаются в старом кодовом пути.
- Имеются две независимые тестируемые программы NRO из одного исходного
  коммита: обычная и с ARM. CI сравнивает SHA-256 и отклоняет
  ситуацию, в которой флаг не изменил выходной двоичный файл.

## Проверка

Новый GitHub Actions `arm-switch-experiment.yml` собирает обе версии
через devkitA64, проводит проверку контейнера NRO0 и публикует отдельно
два файла NRO. Его прохождение докажет только **компиляцию и структуру**,
но не корректность нажатий в настоящем NeXium.

Следующая обязательная проверка: взять экспериментальный NRO из CI,
запустить две свежие эмулируемые сессии (R и ZL+R), снять настоящие
изображения ARM AMMO 3/3 → 2/3 → 3/3, подтвердить нулевые записи
`battle-progress.a/.b` от тренировки и неизменные кадры обычного R.
Не объявлять режим проверенным до этого испытания.
